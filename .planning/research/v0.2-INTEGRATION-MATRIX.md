# v0.2 Integration Matrix

> **PRE-04.** Created during Phase 1 execution (plan 01-03). This matrix tracks every
> cross-feature combination that must have end-to-end coverage before the v0.2 milestone
> can close. It is the source-of-truth input for the Phase 5 INT-04 closure gate.
>
> **How it works:** Each row names a feature pairing, the future plan that will land the
> integration test, and the current status of that coverage. Phase 5's `/gsd:verify-work 5`
> runs `grep -c "pending"` over this file and asserts a count of zero. A non-zero count
> means the milestone cannot close.

---

## Status Vocabulary

Only three tokens are valid in the Status column. The Phase 5 INT-04 grep gate matches
these literals exactly — synonyms or casing variants break the gate.

| Token | Meaning |
|-------|---------|
| `tested` | An end-to-end test exists, named in the Test File column, and is GREEN in CI. |
| `pending` | No end-to-end test yet. A future plan listed in Covering Plan will close this cell. |
| `out-of-scope` | This pairing is intentionally not covered in v0.2. Reason explained in Notes. |

## Closure Rule

The six rows above represent the complete set of cross-feature integration paths that must
be covered before v0.2 can close. The following rules are binding on all Phase 2..5 plans.

1. **Cell vocabulary is fixed.** Only `tested`, `pending`, and `out-of-scope` are valid
   Status values. No synonyms, no capitalization variants, no new tokens. The Phase 5
   INT-04 grep gate is `grep -oE "tested|pending|out-of-scope"` — any drift breaks it.

2. **Each Phase 2..5 plan that ships an integration test MUST update its row.** When a
   plan lands a test that closes a `pending` cell, it must:
   - Set Status from `pending` to `tested`
   - Fill the Test File column with the repo-relative path to the test file
     (e.g., `packages/mcp-server/src/__tests__/integration/rank-with-conflicts.test.ts`)
   - The Test File cell must be non-empty when Status is `tested` — the Phase 5 INT-04
     gate also asserts that every `tested` row has a non-empty Test File pointing at a
     file that exists on disk.

3. **`/gsd:verify-work 5` is the milestone-close gate.** It runs two grep assertions:
   - `grep -c "pending" .planning/research/v0.2-INTEGRATION-MATRIX.md` must return `0`
   - Every row with Status `tested` must have a Test File cell that resolves to an
     existing file in the repo (`test -f <Test File path>` must exit 0)
   
   Until both assertions pass, `/gsd:verify-work 5` will not declare the milestone
   complete — even if all individual feature tests are green.
