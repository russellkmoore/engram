<objective>
Wave 3: connect the producer (`mcp-server/remember()`) to the Queue and connect the consumer (`triage-worker`) permanent-failure paths to `markIngestFailed`. This plan closes the loop end-to-end — by the time it commits, a `remember()` call writes the SQLite row sync, fires the Queue message via `ctx.waitUntil`, and any consumer failure (Zod-permanent OR DO-RPC catch on the last allowed attempt) flips the block's `ingest_status` from `pending` to `failed` instead of silently dropping the message.

Purpose: 06-02 shipped the bindings; 06-03 shipped the SQLite surface; this plan wires both into the actual call sites. PIP-02 (latency: `remember()` returns before queue consumer runs), PIP-03 (`MemoryEvent.id` as idempotency key — same UUID as the block row), PIP-04 (Triage Worker writes results back via RPC — no direct SQL), and PIP-05 (no silent drops on retry exhaustion) all land here.

Output: ~25 lines added to `tools.ts` `remember()` (MemoryEvent assembly + waitUntil block + try/catch on the inner queue send); ~4 line retarget of the `ingest()` comment; widened env type + ~40 lines added to `extract.ts` permanent-fail branches; ~50 lines added to `triage-worker/src/index.ts` (try/catch wrap + attempts pre-emption + markIngestFailed call site with its own observability writeAnalytics). No new files.

Critical sequencing: this plan REQUIRES 06-02 (env.INGEST_QUEUE binding + getCtx accessor on registerTools) AND 06-03 (markIngestFailed RPC on WorkspaceDO) to be committed first. Wave 3 cannot start until both commits land.
</objective>
