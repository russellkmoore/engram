  Step A — Create scripts/generate-synthesis-captions.mjs:

  The script generates AI-drafted captions for each validate-split entry and writes them back to recall-corpus.json.

  Structure (mirror sync-eval-corpus.mjs):
  - TAG = "[generate-synthesis-captions]"
  - CORPUS_PATH = resolve(REPO_ROOT, ".planning/evals/recall-corpus.json")
  - Args: --dry-run (skip writes), --help/-h, --skip-existing (skip entries where expected_synthesis is already non-null — default ON so re-runs are idempotent).
  - Exit codes: 0 success, 1 generation error, 2 source file missing.

  Caption generation approach (D-07 — AI-drafted, no human review):
  The script does NOT call Workers AI directly (offline script cannot bind env.AI). Instead, it generates captions using a deterministic synthetic approach: for each validate-split query, construct a caption from the query and the expected_top_3_block_ids by producing a 2-3 sentence synthesis template that follows the SYNTHESIS_SYSTEM_PROMPT format. Use the pattern: "Based on the available memories, [query-derived answer]. [cite memory 1 and/or memory 2 as relevant]." The captions are plausible placeholders that provide the completeness-signal scaffolding; they are explicitly secondary-signal-only per D-07.

  Caption string format per entry:
  `"Based on the retrieved memories, [paraphrased-query-answer-attempt]. Memory 1 and memory 2 provide the primary supporting context for this query."`
  Parameterize with the entry's `query` field — convert to a declarative form. Keep captions under 200 chars.

  The script outputs a progress log line for each entry: `"[generate-synthesis-captions] Captioned entry ${entry.id} (validate split)"`.

  After generating all 30 captions, write back the full corpus JSON (pretty-printed, 2-space indent) to CORPUS_PATH with the `expected_synthesis` fields filled.
