<objective>
PRE-03 is the single biggest de-risk lever for the entire v0.2 milestone (per ROADMAP risk note). Phase 2/3/4/5 eval gates (Vectorize recall F1, hybrid rank effectiveness, synthesis quality, conflict-detection precision) all draw their statistical confidence from this corpus. With only 47 entries today (20 reference + 27 real), every per-bucket assertion is too noisy to defend; a single mislabeled row can flip a milestone-close gate. Expanding to ≥100 with a 70/30 stratified split makes the gates statistically meaningful.

**Labeling policy (amended 2026-06-03):** The plan was originally structured around full manual labeling. After Task 3 surfaced the realistic effort (~3-4hr fatiguing pass on synthetic fixtures), the policy was amended to **AI cross-validation with human adjudication**: two independent labeler agents (Sonnet + Opus, different model families from the system under test which uses `@cf/qwen/qwen3-embedding-0.6b`) draft `expected_top_3_block_ids` in parallel; entries where both labelers fully agree are auto-accepted; entries where they disagree are surfaced to Russell for ~15-minute adjudication. This preserves the non-circularity property (different model families) while replacing fatiguing manual work with consistent AI judgment plus targeted human oversight. The eval-fixtures workspace still exists so block IDs are stable opaque IDs (Pitfall 4 — labeling against production workspaces means IDs drift the next time re-ingest happens). The schema is locked before labeling begins so a future schema migration doesn't invalidate the labels.

`expected_synthesis: null` is reserved for Phase 4 SYN-01. Phase 1 does not label synthesis; the field is in the schema so Phase 4 can extend without a breaking-schema migration.
</objective>

<amended_threat_t-03-auto>
**Amendment date:** 2026-06-03
**Amendment trigger:** After Task 3 placed 65 placeholder entries on disk, the realistic effort to manually label 100 synthetic queries against 120 synthetic fixtures was estimated at ~3-4hr of fatiguing work. The original T-03-AUTO mitigation assumed ground-truth labeling captured user-specific judgment, but the corpus is built from REDACTED-CORP synthetic fixtures, not real user memories. The integrity concern is **non-circularity** (labels not produced by the system under test), not "100% manual."

**New policy:** Two independent labeler agents (Sonnet + Opus) draft labels in parallel. For each of the 100 entries:

- If both labelers return the same 3 IDs (as a set, order-independent): auto-accept, `labeled_by: "ai-cross-validated:auto-accept"`
- If labelers disagree on any ID: surface (query, labeler-1 picks, labeler-2 picks, both labelers' reasoning) to Russell for ~30-second adjudication, `labeled_by: "ai-cross-validated:rmoore-adjudicated"`
- For carry-forward entries with a pre-existing real ID (e.g., `["ef-001", "ef-PENDING-LABEL", "ef-PENDING-LABEL"]`), the labelers fill the two placeholder slots; the existing ID is preserved
- PII review for prod-log-sourced queries (rcv2-066..rcv2-100) still required — that mitigation (T-01-03) is unchanged

**Non-circularity argument:** The system under test is Workers AI's `@cf/qwen/qwen3-embedding-0.6b` model + hybrid rerank. The labelers are Anthropic's Claude Sonnet 4.6 and Claude Opus 4.7 — different model family, different training corpus, different parameter scale. They produce semantic-relevance judgments via reasoning, not via embeddings. Cross-validation between two Anthropic models is weaker than cross-vendor validation but stronger than single-model labeling, and crucially, **neither labeler is the system under test**.
</amended_threat_t-03-auto>
