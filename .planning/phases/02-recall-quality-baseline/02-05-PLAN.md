<objective>
Build the WorkspaceDO write + read primitives that CON-02 (conflict-pipeline orchestrator in Plan 02-06) and CON-05 (recall envelope SQL-join in Plan 02-08) will call.

Two new helpers in `packages/workspace-do/src/queries.ts`:
1. **`insertConflictAsInbox`** (CON-04 writer) — INSERT a row into the existing `inbox` table with `proposed_type='conflict'`. Mirrors the `createInboxEntry` pattern at `queries.ts:480-491` for at-least-once delivery safety.
2. **`listInboxConflictsForMemoryIds`** (CON-05 reader) — SELECT inbox rows where `proposed_type='conflict'` AND created_at > now-60d, return TS-side-filtered subset whose `proposed_properties.memory_a_id` or `.memory_b_id` ∈ the input id list. Returns raw row shape (not the `Conflict` envelope type — that mapping happens in the recall handler in Plan 02-08).

The contract bridge between writer and reader is the new `InboxConflictProperties` interface in `@engram/types`. Both helpers consume/produce that exact shape, eliminating the manual-contract drift risk per RESEARCH §Pitfall 5.

Both helpers exposed as RPC methods on the `WorkspaceDO` class so cross-Worker callers (`triage-worker` via `env.WORKSPACE` binding, and `mcp-server` via the same binding from `recall()`) can invoke them. The cross-Worker RPC binding pattern is already wired from Phase 1.

This plan is purely DO-side wiring + unit testing. No conflict-pipeline orchestration yet (Plan 02-06), no triage-worker wiring (Plan 02-07), no recall envelope changes (Plan 02-08).
</objective>

       Append the two helpers AFTER the existing `listConflicts` helper (around line 530+):

       ```typescript
       import type { InboxConflictProperties } from "@engram/types";
       import type { InboxConflictRow } from "./types.js";

       /**
        * Insert a conflict-pipeline contradiction into the inbox table.
        *
        * CON-04 contract: only contradictions reach this helper. benign_update
        * and unrelated verdicts MUST be filtered out by the caller.
        *
        * The id is `conflict-<crypto.randomUUID()>` so concurrent writes for the
        * same memory pair don't collide. INSERT OR IGNORE handles at-least-once
        * Queue redelivery for the safety case where the same memory ID arrives
        * twice within one second.
        */
       export function insertConflictAsInbox(
         sql: SqlStorage,
         args: InboxConflictProperties,
       ): void {
         const id = `conflict-${crypto.randomUUID()}`;
         const proposed_properties = JSON.stringify({
           memory_a_id: args.memory_a_id,
           memory_b_id: args.memory_b_id,
           category: args.category,
           ai_confidence: args.ai_confidence,
           description: args.description,
         });
         sql.exec(
           `INSERT OR IGNORE INTO inbox
              (id, content, proposed_type, proposed_properties, memorability_score, source, created_at)
            VALUES (?, ?, ?, ?, ?, ?, ?)`,
           id,
           args.description,
           "conflict",
           proposed_properties,
           args.ai_confidence,
           "triage:conflict-pipeline",
           Date.now(),
         );
       }

       /**
        * CON-05 read helper. Returns inbox rows tagged as conflicts whose
        * `proposed_properties.memory_a_id` or `.memory_b_id` matches one of the
        * input ids.
        *
        * Implementation per RESEARCH §Pattern 6 Option A: TS-side filter after
        * a bounded SELECT. JSON-extract via SQL would require json_extract
        * (uncertain workerd-build availability per RESEARCH §A3); the TS-side
        * filter is robust and the scan ceiling (60-day window + LIMIT 100)
        * keeps cost bounded.
        */
       export function listInboxConflictsForMemoryIds(
         sql: SqlStorage,
         args: { ids: string[] },
       ): InboxConflictRow[] {
         if (args.ids.length === 0) return [];
         const since = Date.now() - 60 * 24 * 3600 * 1000;
         const rows = sql
           .exec(
             `SELECT id, content, proposed_type, proposed_properties, memorability_score, source, created_at
              FROM inbox
              WHERE proposed_type = 'conflict' AND created_at > ?
              ORDER BY created_at DESC
              LIMIT 100`,
             since,
           )
           .toArray() as unknown as InboxConflictRow[];
         const idSet = new Set(args.ids);
         return rows.filter((row) => {
           try {
             const parsed = JSON.parse(row.proposed_properties) as InboxConflictProperties;
             return idSet.has(parsed.memory_a_id) || idSet.has(parsed.memory_b_id);
           } catch (err) {
             console.warn("listInboxConflictsForMemoryIds:parse-failed", {
               id: row.id,
               err: err instanceof Error ? err.message : String(err),
             });
             return false;
           }
         });
       }
       ```
