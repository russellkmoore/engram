<objective>
Build the `conflictPipeline` orchestrator that composes Plan 02-01's `vectorizeNeighbors` helper, the existing `detectConflict()` inference (untouched per CON-01), Plan 02-05's `insertConflictAsInbox` RPC, and the triage-worker's `writeAnalytics` pattern into a single fire-and-forget routine. Called by Plan 02-07 via `ctx.waitUntil(conflictPipeline(env, newBlock))`.

CON-02 flow:
1. **Embed** — call `env.AI.run(EMBEDDING_MODEL, { text: [newBlock.content] })` ONCE at the top of the pipeline to produce the qwen3-embedding-0.6b vector for `newBlock.content`. The vector is consumed only by the immediately-following `vectorizeNeighbors` call; never stored.
2. Cosine prefilter — `vectorizeNeighbors(env, workspace_id, embedding, { topK: 3, type: newBlock.type, scope: newBlock.scope, threshold: 0.7 })`.
3. CON-06 dupe-ceiling — drop matches at ≥0.92 cosine (PITFALLS CD-4).
4. Hydrate neighbor blocks via cross-Worker `WORKSPACE.getBlocksByIds` RPC (existing pattern).
5. Bounded-parallel CON-07 — `Promise.all` over up to 3 `detectConflict()` calls. The `topK=3` prefilter ceiling IS the concurrency cap; no `p-limit` needed.
6. For every `category === "contradiction"` verdict, call `insertConflictAsInbox` RPC with the CON-04 shape (Plan 02-05 contract).
7. D-20 analytics — emit `writeDataPoint` in `finally` so the row lands even on error.

Verdict enum: `"contradiction" | "benign_update" | "unrelated" | "skipped-dupe" | "error"`. The verdict is computed AFTER the parallel detect resolves; it's the "highest-severity-seen-so-far" — `error` overrides everything; `contradiction` overrides `benign_update`; `unrelated` is the no-op-but-not-skipped baseline; `skipped-dupe` indicates the dupe filter blocked all candidates; `unrelated` covers "no neighbors above threshold" too.

CON-08 architectural lock: NO `EMAIL`, `WEBHOOK`, `PUSH`, `NOTIFY`, `SLACK`, or any push-notification primitive is imported or invoked anywhere in this file. The only output sinks are: the WorkspaceDO inbox table (via RPC) and the Analytics Engine.

The orchestrator runs INSIDE the `ctx.waitUntil` callback (wired in Plan 02-07). RESEARCH §Pitfall 6 is the load-bearing rule: `writeAnalytics` MUST be inside the function body (which runs inside waitUntil) so the lifetime guarantee holds. Errors are CAUGHT LOCALLY — never re-thrown — because a throw inside waitUntil marks the parent invocation as failed.

**Why embedding is computed internally (Path A — see Revision log):** Reconnaissance of `packages/triage-worker/src/extract.ts` and `packages/triage-worker/src/index.ts` confirmed the triage-worker does NOT compute the block embedding anywhere in the queue-consumer path (`extractAndScore` only calls `CLASSIFIER_MODEL`; no `EMBEDDING_MODEL` call exists). The embedding therefore cannot be "exposed" by the caller without a structural rework of the upstream queue path. The clean fix is to compute it ONCE inside `conflictPipeline` immediately before the Vectorize call. Cost: +1 AI call per store-normal write (~150ms — well within CON-07 4s p99 budget; the call already runs through the existing 429-retry envelope). Trade-off: minor latency cost in exchange for a clean Plan 02-07 wiring (no extract.ts mutation; no cross-plan circular contract).
