The Triage Worker (extended in 06-04) and the integration tests (06-05) both depend on `markIngestFailed` RPC existing and on `updateBlockEnrichment` / `moveToInbox` / `moveToColdStorage` carrying the `ingest_status='enriched'` SET clause. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Triage Worker → `WorkspaceDO.markIngestFailed` RPC | Cross-Worker DO call; the `workspace_id` argument arrives in the `MemoryEvent` body (populated by the mcp-server producer from JWT-derived `props.workspace_id`). STO-07 `assertOwnsWorkspace` is the data-plane backstop. |
| `markIngestFailed.reason` field → SQLite `properties` column | The `reason` string is constructed by the Triage Worker (`"zod-parse-fail: ${parsed.error.issues[0]?.message}"` or `"do-rpc-${decision}: ${err.message}"`). It originates from a Cloudflare-internal error (AI binding) or a server-side string — never directly from user input — but it is persisted to SQLite via `JSON.stringify({error: reason, ...})` and later read back for v0.2 inbox UI display. |
| `createInboxEntry` → `inbox.id` PK | `inbox.id` equals `block.id` (per `moveToInbox` composition). Duplicate Queue delivery would otherwise raise a UNIQUE constraint failure that crashes the Triage Worker. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-WS-INJECT | Spoofing / Elevation of Privilege | `markIngestFailed` RPC | mitigate | `assertOwnsWorkspace(args.workspace_id)` is the FIRST EXECUTABLE LINE — verified by the new defense-in-depth test. The Triage Worker passes `event.workspace_id` (from the Queue message body, populated by the producer from `props.workspace_id`); STO-07 guarantees the DO bound to `idFromName(X)` only accepts `workspace_id === X`. Cross-workspace markIngestFailed is impossible by construction. |
