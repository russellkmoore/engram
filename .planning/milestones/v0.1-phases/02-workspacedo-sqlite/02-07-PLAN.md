<!-- Forbidden tokens (D-10 — locked): -->

```
env.
fetch(
await this.ai
await ctx.storage.transaction(
await import(
await this.env
```

<!-- Allowed inside the block: -->
- synchronous storage.sql.exec(...) — no await
- pure JS expressions / loops / assignments
- console.log calls

<!-- Block extraction approach (D-09 + PATTERNS.md §1 — balance-counted regex, NOT ts-morph): -->

1. Find every occurrence of `blockConcurrencyWhile(async () => {` (or `blockConcurrencyWhile(async function ... {`).
2. From the opening `{` of the arrow body, scan forward counting braces (`{` = +1, `}` = -1) until depth reaches 0.
3. The substring between the opening and matching close `}` is the block body.
4. Run each forbidden-token check against the block body (substring match — escape regex special chars; whole-word boundaries where applicable for `env.` so `process.env.` doesn't match).
5. Report violations with file path + offset + the matched token.

<!-- Script dispatch (mirrors lint-wrangler.mjs lines 22-49): -->

- 0 positional args → `fast-glob("packages/workspace-do/src/**/*.ts")`. Exit 2 if matched.length === 0 (canary).
- ≥1 positional args → lint exactly those files.
- Per file: read text, find blocks, check tokens, count violations.
- Final: exit 0 if violations === 0, exit 1 if violations > 0 (in positional or no-arg mode), exit 2 only from no-arg mode with zero matches.

<!-- Important: the no-arg glob `packages/workspace-do/src/**/*.ts` WOULD match the test files in src/__tests__/. -->
<!-- Fixtures are intentionally in `packages/workspace-do/__fixtures__/` (NOT src/) per Plan 00 — so they are NOT picked up by the no-arg glob. -->
<!-- Test files themselves DO get scanned by the no-arg glob — but they contain no blockConcurrencyWhile calls, so the lint passes them. -->
<!-- If a test file is added that exercises blockConcurrencyWhile (e.g., a future inline mock), the lint would scan its block body and either pass (sync-only) or fail (if it intentionally violates for a test scenario). The test author can avoid the false-positive by NOT calling blockConcurrencyWhile in test files. -->

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07-01 | Tampering | Regex bypass — comment with forbidden token | mitigate | Script strips line comments + block comments from extracted block bodies before the token check (Task 1 implementation note). A doc comment saying `// do not call env.AI here` no longer false-positives. |
| T-02-07-02 | Tampering | Author wraps forbidden token in template literal | accept | A template literal containing `env.` would NOT execute env access at runtime, but the lint would still match it. | T-02-07-03 | Spoofing | Lint passes a file that does NOT contain blockConcurrencyWhile but has env. in regular code | accept | The script only checks tokens INSIDE blockConcurrencyWhile blocks. Files without that pattern produce zero block bodies and pass cleanly. This is the intended scoping (Pitfall 1's narrow defense). Other DO best-practice rules (no I/O in storage callbacks, etc.) are out of scope for STO-10. |
| T-02-07-04 | DoS | Pathological brace matching in a malformed file | accept | The balance-counted regex scans linearly through text; runtime is O(file size). The largest TS file in the repo is small (<5KB); even a 1MB file would complete in milliseconds. No pathological-input risk surfaces in this codebase. |
