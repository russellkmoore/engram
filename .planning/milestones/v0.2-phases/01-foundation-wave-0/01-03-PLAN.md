<objective>
PRE-04 is the only Phase 1 deliverable that does not exist in any prior milestone as a template. Phase 2 ships ranking + conflict detection, Phase 3 ships export + workspaces, Phase 4 ships synthesis, Phase 5 ships AI integration — each is largely tested in isolation. The integration matrix is the doc that tracks _what combinations get end-to-end coverage by milestone close_. Without it, individual features can pass their own tests while the kitchen-sink path (a recall query that triggers ranking → conflict detection → synthesis → export, all in one request) is silently uncovered.

The matrix is deliberately small (six pairings) because Phase 5's INT-04 closure gate runs `grep -c "pending"` to assert zero pending rows. A bigger matrix dilutes that signal. The cell vocabulary (`tested | pending | out-of-scope`) is byte-fixed for the same reason: Phase 5 INT-04 greps for the literal strings. Divergence breaks the gate.
</objective>

<!-- Six pairings (from RESEARCH and CLAUDE.md feature inventory): -->

| Pairing key | Components | Why it matters |
|-------------|-----------|----------------|
| RNK × CON | Ranking + Conflict Detection | A recall that surfaces conflicts must hybrid-rank AFTER conflict detection enriches the result; without coverage, ranking can sort conflicts away. |
| RNK × EXP | Ranking + Export | An export filtered by query (search-style) must use the same ranking the live recall path uses; divergence = "what I saw in chat" ≠ "what I exported". |
| EXP × SYN | Export + Synthesis | An exported reflection must include the synthesis layer at export time; otherwise the exported markdown is data-only and loses the "Engram returns insights" principle. |
| CON × SYN | Conflict Detection + Synthesis | When synthesis is asked for a topic with detected conflicts, the response must surface them (not paper over). |
| kitchen-sink | All four | The full pipeline: query → ranked recall → conflict-enrichment → synthesis → returned EngramResponse. The most realistic Claude-as-MCP-client path. |
| adaptive-routing × cosine-edge | AI helper 429-routing + Vectorize cosine edge cases | Phase 5 AI integration's dual-path 429 logic plus the embedding-edge cases (e.g., near-duplicate cosine scores) — coverage closes the "what happens when both go wrong at once?" gap. |
